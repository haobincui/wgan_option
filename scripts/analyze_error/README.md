# analyze_error

This directory contains the post-training surface error analysis workflow for the project.

It supports two analysis modes:

- `vol`: compare the target vol surface in `merged_vol.xlsx` against the future vol surface generated by the trained WGAN
- `svi`: predict future SVI parameters with the trained regressor, reconstruct them into a future vol surface, and compare that surface against the real future SVI-reconstructed vol surface

Unified entrypoint:

```bash
python scripts/analyze_error/main.py vol --config configs/analyze_error/vol.yaml
python scripts/analyze_error/main.py svi --config configs/analyze_error/svi.yaml
```

## Run Flow

One `analyze_error` run follows this fixed sequence:

1. Load the analysis config.
2. Load workbook rows and sort them chronologically.
3. Apply `split` and `selection_mode` to choose the samples to analyze.
4. Resolve the checkpoint path.
5. Re-run model inference to produce generated future surfaces.
6. Compute the signed error surface and per-sample error metrics.
7. Write `errors.csv`.
8. Run bootstrap on the sample-level `mse` values.
9. Write bootstrap summary and bootstrap distribution outputs.
10. Render two histograms:
   - `mse_histogram.png`
   - `bootstrap_mean_mse_histogram.png`

The output is written into a timestamped run directory such as:

```text
outputs/analyze_error/vol/20260408_132827/
outputs/analyze_error/svi/20260408_132827/
```

## vol Mode Logic

Implementation entrypoint: `scripts/analyze_error/analyze_vol.py`

Data loading:

- Read rows from `merged_vol.xlsx`, typically from the `gan_input_ready` sheet.
- Keep only rows with `training_candidate_flag == 1`.
- Sort rows by `news_timestamp_utc`.
- Treat each remaining row as a ready-made paired sample with:
  - `current_surface_flat`
  - `target_surface_flat`

Inference:

- Resolve the generator checkpoint from either:
  - `checkpoint_path`
  - `best_checkpoint.json`
  - fallback filenames such as `generator_best.pt`
- Rebuild the generator using the training config saved inside the checkpoint.
- For each sample, feed:
  - the current vol surface
  - the text embedding
  - deterministic noise

The noise is deterministic per sample:

```text
sample_seed = config.seed + sample.global_index
```

This makes inference reproducible for the same config, checkpoint, and sample order.

Comparison target:

- `target_surface`: the real future vol surface from the workbook
- `generated_surface`: the future vol surface produced by the generator

Signed error definition:

```text
error_surface = target_surface - generated_surface
```

## svi Mode Logic

Implementation entrypoint: `scripts/analyze_error/analyze_svi.py`

Data loading:

- Read rows from `merged_svi.xlsx`, typically from the `news_direction_audit` sheet.
- Keep only rows with `training_candidate_flag == 1`.
- Pair rows by `news_row_id`:
  - `backward` is treated as current
  - `forward` is treated as future
- Sort the paired samples chronologically.

So in `svi` mode, one analyzed sample is a `backward/current -> forward/future` pair, not a single workbook row.

Inference:

- Load the saved `svi_regressor` checkpoint.
- Recover these checkpoint values:
  - `embedding_dim`
  - `max_slices`
  - `normalization_stats`
- Build the current-state feature vector from current SVI parameters:
  - organize values in `SVI_FEATURE_ORDER`
  - normalize them
  - append the slice mask
  - append the normalized slice-count feature
- Run the model to obtain:
  - `predicted_regression`
  - `predicted_count_logits`
- Convert `predicted_count_logits` into a predicted slice count with:

```text
predicted_count = argmax(predicted_count_logits) + 1
```

- De-normalize the regression output to recover predicted future SVI parameters.

Surface reconstruction:

Before error computation, both predicted and real future SVI parameters are reconstructed onto a fixed vol-surface grid defined by:

- `strike_bins`
- `maturity_bins`
- `moneyness_min`
- `moneyness_max`
- `maturity_min_days`
- `maturity_max_days`

Then the comparison is:

- `generated_surface`: the surface reconstructed from predicted future SVI
- `target_surface`: the surface reconstructed from real future SVI

Signed error definition remains:

```text
error_surface = target_surface - generated_surface
```

## MSE and Other Error Metrics

Shared logic lives in `scripts/analyze_error/common.py` inside `compute_error_metrics()`.

For each sample, the analysis first forms a 2D signed error surface:

```text
error_surface[i, j] = target_surface[i, j] - generated_surface[i, j]
```

The reported metrics are then computed over all grid cells in that surface.

MSE:

```text
mse = mean(error_surface^2)
```

RMSE:

```text
rmse = sqrt(mean(error_surface^2))
```

MAE:

```text
mae = mean(abs(error_surface))
```

Maximum absolute error:

```text
max_abs = max(abs(error_surface))
```

Signed error distribution statistics:

```text
error_mean = mean(error_surface)
error_std  = std(error_surface)
error_min  = min(error_surface)
error_max  = max(error_surface)
```

The surface shape is also recorded:

```text
surface_rows
surface_cols
```

## Bootstrap Logic

Bootstrap is implemented in `scripts/analyze_error/bootstrap.py`.

Bootstrap unit:

- sample-level `mse`

The workflow first extracts:

```text
mse_values = [row_1.mse, row_2.mse, ..., row_n.mse]
```

where `n` is the number of analyzed samples.

One bootstrap replicate:

1. Sample `n` values from `mse_values` with replacement.
2. Compute the mean of that resampled set.
3. Store that mean as one bootstrap statistic.

Formally:

```text
bootstrap_mean_mse_b = mean(sample_with_replacement(mse_values, size=n))
```

This is repeated `bootstrap_samples` times, producing:

```text
distribution = [mean_mse_1, mean_mse_2, ..., mean_mse_B]
```

Default setting:

```text
bootstrap_samples = 10000
```

The bootstrap answers the question:

- given the observed set of sample-level MSE values, what is the uncertainty around the overall mean MSE?

The resampling unit is the sample row, not the individual surface grid cell.

Confidence interval:

The current implementation uses a percentile confidence interval, not BCa.

If:

```text
alpha = 1 - confidence_level
```

then:

```text
ci_lower = quantile(distribution, alpha / 2)
ci_upper = quantile(distribution, 1 - alpha / 2)
```

Default:

```text
confidence_level = 0.95
```

## Bootstrap Outputs

Summary outputs:

- `bootstrap_summary.csv`
- `bootstrap_summary.json`

Fields:

- `sample_count`
- `bootstrap_samples`
- `confidence_level`
- `observed_mean_mse`
- `bootstrap_mean`
- `bootstrap_std`
- `ci_lower`
- `ci_upper`
- `seed`

Meaning:

- `observed_mean_mse`: direct mean of the original sample-level MSE values
- `bootstrap_mean`: mean of the bootstrap distribution
- `bootstrap_std`: standard deviation of the bootstrap distribution
- `ci_lower`, `ci_upper`: percentile confidence interval bounds

If `save_bootstrap_distribution = true`, the run also writes:

- `bootstrap_distribution.csv`

Granularity:

- one row = one bootstrap replicate

Fields:

- `replicate_index`
- `mean_mse`

## Histogram Logic

Histogram plotting is implemented in `scripts/analyze_error/plotting.py`.

Two histograms are produced automatically.

### mse_histogram.png

Data source:

- sample-level `mse` values from `error_rows`

Meaning:

- distribution of per-sample MSE across all analyzed timestamps

Figure settings:

- title: `Sample-level MSE Distribution`
- x-axis: `MSE`
- y-axis: `Count`
- one vertical line at the sample mean MSE

Output filename:

```text
mse_histogram.png
```

### bootstrap_mean_mse_histogram.png

Data source:

- the bootstrap `distribution`

Meaning:

- distribution of the bootstrapped mean MSE statistic

Figure settings:

- title: `Bootstrap Mean MSE Distribution`
- x-axis: `Bootstrap Mean MSE`
- y-axis: `Count`
- one vertical line for `observed_mean_mse`
- one vertical line for `ci_lower`
- one vertical line for `ci_upper`

Output filename:

```text
bootstrap_mean_mse_histogram.png
```

Important detail:

- even if `save_bootstrap_distribution = false`
- as long as `save_bootstrap_histogram = true`

the histogram can still be drawn directly from the in-memory bootstrap distribution.

## Example Commands

Run `vol` analysis:

```bash
python scripts/analyze_error/main.py vol --config configs/analyze_error/vol.yaml
```

Run `svi` analysis:

```bash
python scripts/analyze_error/main.py svi --config configs/analyze_error/svi.yaml
```

Override bootstrap size:

```bash
python scripts/analyze_error/main.py vol \
  --config configs/analyze_error/vol.yaml \
  --set bootstrap_samples=2000
```

Override histogram bins:

```bash
python scripts/analyze_error/main.py svi \
  --config configs/analyze_error/svi.yaml \
  --set histogram_bins=20
```

Disable bootstrap distribution CSV while keeping histogram output:

```bash
python scripts/analyze_error/main.py vol \
  --config configs/analyze_error/vol.yaml \
  --set save_bootstrap_distribution=false
```

## Short Statistical Summary

The current statistical convention of `analyze_error` is:

1. Build the signed error surface

```text
error_surface = target_surface - generated_surface
```

2. Compute the sample-level MSE

```text
mse = mean(error_surface^2)
```

3. Collect all sample-level MSE values into `errors.csv`
4. Bootstrap the mean of those sample-level MSE values
5. Output:
   - per-sample error table
   - bootstrap summary
   - bootstrap distribution
   - sample-level MSE histogram
   - bootstrap mean-MSE histogram

That is the full current implementation logic for MSE, bootstrap, and histogram generation in this directory.
